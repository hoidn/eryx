# Command: /review-phase-gemini [optional-phase-number] <initiative-path>

**Goal:** Autonomously perform a rigorous peer review of a project phase, generating a formal review document with a clear verdict that can be processed by the `/complete-phase` command.

**Usage:**
-   **Automatic (Recommended):** `/review-phase-gemini plans/active/my-initiative`
-   **Manual Override:** `/review-phase-gemini 2 plans/active/my-initiative`

**Prerequisites:**
-   A `review_request_phase_[N].md` file must have been generated by `/complete-phase`.
-   For automatic mode, `PROJECT_STATUS.md` must exist and contain a valid `Current Phase:` line.

---

## 🔴 **CRITICAL: MANDATORY EXECUTION FLOW**

**YOUR ROLE IS TO ORCHESTRATE THE REVIEW, NOT PERFORM IT YOURSELF.**
1.  You MUST determine the target phase number, either from the user's argument or by parsing `PROJECT_STATUS.md`.
2.  You MUST locate and read the corresponding `review_request_phase_[N].md` file.
3.  You MUST build a structured prompt file (`review-prompt.md`) using the content of the review request.
4.  You MUST execute `gemini -p "@review-prompt.md"` to delegate the entire review process.
5.  You MUST save Gemini's response **exactly as provided** to `review_phase_[N].md`.

**DO NOT:**
-   ❌ Make your own judgment on the code changes.
-   ❌ Modify Gemini's verdict or comments.
-   ❌ Skip the `gemini` execution for any reason.

---

## 🤖 **YOUR EXECUTION WORKFLOW**

### Step 1: Determine Target Phase & Locate Review Request

This step intelligently parses the user's input to determine the target phase and load the necessary context file.

```bash
# Ensure a temporary directory exists for our files
mkdir -p ./tmp

# --- Argument Parsing Logic ---
PHASE_NUMBER=""
INITIATIVE_PATH=""

# Check number of arguments to determine mode (automatic or manual)
if [ "$#" -eq 1 ]; then
    # Automatic Mode: Only the path was provided.
    INITIATIVE_PATH="$1"
    echo "ℹ️ No phase number provided. Auto-detecting current phase from PROJECT_STATUS.md..."
    
    # Parse the phase number from the status file.
    # This robust command looks for "Current Phase: Phase X" and extracts the number X.
    PHASE_NUMBER=$(grep 'Current Phase:' PROJECT_STATUS.md | sed 's/.*Phase \([0-9]*\).*/\1/')

    # CRITICAL: Verify that parsing was successful.
    if ! [[ "$PHASE_NUMBER" =~ ^[0-9]+$ ]]; then
        echo "❌ ERROR: Could not automatically determine the current phase number from PROJECT_STATUS.md."
        echo "Please ensure the 'Current Phase:' line is correctly formatted (e.g., 'Current Phase: Phase 1: ...')."
        exit 1
    fi
    echo "✅ Automatically detected current phase as: Phase $PHASE_NUMBER"

elif [ "$#" -eq 2 ]; then
    # Manual Mode: Both phase and path were provided.
    PHASE_NUMBER="$1"
    INITIATIVE_PATH="$2"
    echo "✅ Using explicitly provided phase number: $PHASE_NUMBER"
else
    echo "❌ ERROR: Invalid number of arguments."
    echo "Usage: /review-phase-gemini [optional-phase-number] <initiative-path>"
    exit 1
fi

# --- Load Context File ---
REVIEW_REQUEST_PATH="$INITIATIVE_PATH/review_request_phase_${PHASE_NUMBER}.md"

# Verify the review request file exists
if [ ! -f "$REVIEW_REQUEST_PATH" ]; then
    echo "❌ ERROR: Review request file for Phase $PHASE_NUMBER not found at '$REVIEW_REQUEST_PATH'."
    echo "Please run /complete-phase first to generate the review request."
    exit 1
fi

# Read the entire content of the review request.
REVIEW_REQUEST_CONTENT=$(cat "$REVIEW_REQUEST_PATH")

echo "✅ Successfully loaded review request for Phase $PHASE_NUMBER."
```

### Step 2: MANDATORY - Build the Prompt File

You will now build the prompt for Gemini in a file using the structured XML pattern.

```bash
# Clean start for the prompt file
rm -f ./review-prompt.md 2>/dev/null

# Create the structured prompt with placeholders
cat > ./review-prompt.md << 'PROMPT'
<task>
You are a meticulous and strict Senior Peer Reviewer. Your task is to review the provided code changes and planning documents for a software development phase and provide a definitive verdict.

<steps>
<1>
Thoroughly analyze all the provided context in `<review_request_context>`, which includes the R&D plan, implementation plan, phase checklist, and a complete `git diff` of all code changes.
</1>
<2>
Compare the code changes against the stated goals in the planning documents. Verify that all checklist items have been addressed by the code changes.
</2>
<3>
Critically assess the code quality for correctness, clarity, maintainability, and adherence to project standards.
</3>
<4>
Generate a formal review document that strictly adheres to the format specified in `<output_format>`. This is not optional.
</4>
</steps>

<review_request_context>
[Placeholder for the content of review_request_phase_N.md]
</review_request_context>

<output_format>
Your entire response must be a single Markdown block.
The most important line of your output MUST be `VERDICT: [ACCEPT|REJECT]`.
Do not include any conversational text before or after your review.

# Review: Phase [Phase Number] - [Phase Name]

**Reviewer:** Gemini Automated Reviewer
**Date:** [Current Date YYYY-MM-DD]

## Verdict

**VERDICT: [ACCEPT|REJECT]**

---
## Comments

[Provide a concise summary of your findings. If ACCEPT, explain why the changes are good. If REJECT, briefly state the primary reason for rejection.]

---
## Required Fixes (if REJECTED)

[If the verdict is REJECT, you MUST provide a bulleted list of specific, actionable fixes. Each item should reference the file and line number if possible. If the verdict is ACCEPT, this section should be empty or state "None."]
- **Fix 1:** In `path/to/file.py:42`, the error handling is incomplete. It must also catch `SomeSpecificError`.
- **Fix 2:** The new unit test `tests/test_new_feature.py` does not cover the specified edge case from the implementation plan.

</output_format>
</task>
PROMPT

# Inject the review request content into the prompt file.
# Using a temp file handles multi-line variables and special characters safely.
echo "$REVIEW_REQUEST_CONTENT" > ./tmp/review_req.txt
sed -i.bak -e '/\[Placeholder for the content of review_request_phase_N.md\]/r ./tmp/review_req.txt' -e '//d' ./review-prompt.md

echo "✅ Successfully built structured prompt file: ./review-prompt.md"
```

### Step 3: MANDATORY - Execute Gemini Review

You MUST now execute Gemini using the single, clean, and verifiable prompt file.

```bash
# Execute Gemini with the fully-formed prompt file
gemini -p "@./review-prompt.md"
```

### Step 4: Save the Official Review Document

Your final role: receive the output from your command and save it without modification.

```bash
# [You will receive Gemini's review document as a response from the command above]
# For this example, we'll assume the response is captured into $GEMINI_RESPONSE.

# Define the output path
OUTPUT_PATH="$INITIATIVE_PATH/review_phase_${PHASE_NUMBER}.md"

# Save the review exactly as received.
echo "$GEMINI_RESPONSE" > "$OUTPUT_PATH"

# Verify the file was saved
if [ ! -s "$OUTPUT_PATH" ]; then
    echo "❌ ERROR: Failed to save Gemini's output to '$OUTPUT_PATH'."
    exit 1
fi

echo "✅ Saved Gemini's formal review to: $OUTPUT_PATH"
echo ""
echo "The review is complete. You can now run /complete-phase again to process the verdict."
```
